# MiruShin TV — тестовий патч

Окремий проєкт на основі MiruShin 2.9.24. Оригінал:
https://github.com/emp0ry/MiruShin. Робоча копія:
https://github.com/mercs2910/MiruShin/tree/fix/android-external-players.
Ліцензія вихідного проєкту — GPL-3.0, див. `LICENSE`.

## Що змінено

- Локальний вибір плеєра Android: MiruShin, MiruShin із програмним
  декодуванням, Vimu, MX Player, MX Player із програмним декодуванням.
- Цей вибір зберігається окремо від синхронізованих налаштувань і не змінює
  плеєр на Mac.
- Зовнішньому плеєру передаються обрана серія та початкова позиція.
- Підтримано повернення позиції й підтвердження завершення через офіційні
  інтерфейси Vimu та MX. Для MX також передаються заголовки джерела.
- Стан відтворення береться лише із сеансу вибраного плеєра Android. Для
  цього потрібен окремий дозвіл доступу до сповіщень. Текст сповіщень код
  не читає й не зберігає.
- При доступній позиції створюється нативна контрольна точка кожні п'ять
  секунд. Після перезапуску вона відновлюється в бібліотеку лише відповідного
  облікового запису; видаляється після успішного запису в базу даних.
- Пропуск вступу та кінцівки використовує чинні маркери MiruShin і працює,
  якщо зовнішній плеєр надає команду перемотування.
- Зовнішній плеєр не запускає внутрішній декодер чи декодер мініатюр.
- Мову застосунку залишено російською відповідно до побажання користувача.

## Межі підтримки

Внутрішнє програмне декодування зберігає звичайний інтерфейс MiruShin.
Можливості зовнішнього плеєра залежать від його підтримки медіасеансу
Android. Самого результату виходу з плеєра недостатньо для збереження під
час аварії. При вимкненні живлення доступна остання записана контрольна
точка, а не гарантована позиція останнього кадру.

Прогрес не позначається завершеним лише через закриття, помилку чи
відсутність відповіді плеєра. Для автоматичного переходу на наступну серію
зовнішній плеєр має підтвердити завершення.

Тестова збірка має пакет `com.emp0ry.mirushin.diagnostic`, назву
**MiruShin Test** і встановлюється поруч із початковим застосунком.
Вона використовує випусковий режим Flutter й окремий ключ нашого проєкту.
Це не підписана ключем автора заміна офіційного APK.

## Збірка

Потрібні Flutter stable із Dart щонайменше 3.11.4, JDK 17 та Android SDK.
У файлі `android/gradle.properties` для окремої тестової програми потрібно
встановити `mirushinDiagnostic=true`.

Перед збіркою створіть локальний `.env` з полями `TMDB_READ_ACCESS_TOKEN`,
`MODULE_LIBRARY_URL`, `FANART_TV_API_KEY`. Для тесту відтворення ці значення
можуть бути порожніми; типовий каталог модулів та TMDB тоді недоступні.
Модулі можна додати за їхньою відкритою адресою. Ключі та дані користувача
не потрібно додавати в Git.

```sh
flutter pub get
dart run build_runner build --delete-conflicting-outputs
flutter analyze --no-fatal-infos --no-fatal-warnings
flutter test test/external_playback_test.dart test/playback_attempt_plan_test.dart test/auto_skip_test.dart test/player_settings_test.dart test/player_checkpoint_persistence_test.dart
flutter build apk --release --target-platform android-arm
```

Автоматична збірка: GitHub Actions → Build Android APK → гілка
`fix/android-external-players` → параметр `diagnostic=true`.
Сценарій створює `.env` із порожніми значеннями й не використовує
облікові дані користувача або ключ підпису офіційного застосунку.

## Перевірка на приставці

Причина експерименту та узгоджений план описані в
`docs/plans/2026-11-03-android-external-players.md`.
Автоматичні перевірки охоплюють збереження перед виходом, відновлення
контрольної точки після помилки запису, ізоляцію облікових записів,
підтвердження завершення та незалежність налаштувань Android від Mac.

Результати реального відтворення, відновлення позиції й пропусків будуть
записані окремо після встановлення APK та перевірки на RockTek RTD1325.
До цього відсутність ривків і повну сумісність зовнішніх плеєрів не доведено.
